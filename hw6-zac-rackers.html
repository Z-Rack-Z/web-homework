Written answers

In Challenge 8.1, the script in the <head> found nothing until you changed it. Explain why, and describe two different ways to make sure a script runs only after the elements it needs exist.

A plain script in the head runs while the browser is still parsing, before the body paragraph exists, so querySelector returns null. One fix is to use a deferred external script, which runs after parsing. Another is to wrap the code in a DOMContentLoaded listener so it waits until the elements have been created.

A text box gives your script the value '5'. Explain why '5' + 1 and Number('5') + 1 give different results, and why === is a safer way than == to compare values like these.

A text box returns a string. With a string operand, + joins text, so the first expression produces the string 51. Number converts the input to a number first, so the second expression produces the number 6. Strict equality compares both type and value, avoiding surprising coercion such as the string 5 comparing equal to the number 5.

Explain how makeBottle keeps each bottle's water separate and private. Where does the water variable live, and why does it still exist after makeBottle has finished running?

The water variable is local to each call of makeBottle. The returned drink and left methods close over that variable, so it stays alive after makeBottle returns. Each call creates its own private water value; callers can use the methods but cannot directly read or overwrite that local variable.

Explain why you should use textContent rather than innerHTML to show text that a visitor typed. What could go wrong with innerHTML?

textContent treats visitor input as plain text, so angle brackets appear as characters. innerHTML parses it as markup. A malicious visitor could enter HTML with event handlers or scripts, changing the page or running code in another visitor’s browser. Use textContent for user-provided text.

Explain event delegation in your own words. Why does one listener on #filters hear clicks on every button, and why do you need closest() instead of using event.target as it is?

Clicks bubble from the element clicked through its ancestors, so one click listener on #filters hears clicks on every button it contains, including buttons added later. event.target may be the dot span inside a button; closest(button) walks upward to find the button whose data-level should be used.

Your script checks the sign-up form before anything is sent. Explain why the club's server must still check the same data, and how aria-invalid and a text message under each field help a visitor who cannot see a red border.

Browser validation helps visitors correct mistakes, but a request can bypass JavaScript or be altered before reaching the server. The server must validate the same rules before trusting or storing the data. aria-invalid announces that a control is wrong to assistive technology, and a nearby text message explains the specific problem without relying on the border color.
