Written answers

Explain it 1

Browsers quietly repair broken HTML instead of showing an error. Explain why the HTML standard chose to be forgiving, why that is still a problem for you as the author, and which tool shows you the mistakes the browser hides.

HTML is forgiving so people can still read older pages and pages with mistakes instead of seeing an error. The browser's repair may create a different structure than I intended, which can cause layout or accessibility problems even when the page looks fine. I can use the W3C Nu Html Checker to find the markup errors that the browser hides.

Explain it 2

In your own words, explain why checked="false" still ticks a checkbox, and the only way to write "off" for a boolean attribute such as checked, hidden or disabled.

A boolean attribute is true whenever it is present, so checked="false" still tells the browser to check the box. The word "false" does not turn the attribute off. To start with checked, hidden or disabled off, I must leave that attribute out of the HTML entirely.

Explain it 3

The div version and your semantic version of the home page can look exactly the same in a browser. Explain why the semantic version is still better, and name at least two people or programs that benefit from it.

Semantic HTML tells readers and programs what each part of a page means, even when CSS makes it look the same as a page made from divs. Screen reader users can navigate by headings and landmarks, while search engines can better identify the page's structure. It also helps another developer understand the purpose of each section without guessing from class names.

Explain it 4

Explain the difference between <head> and <header>, and between <title> and <h1>. Where does each one appear, and who or what reads it?

The head contains metadata such as the character encoding, description and title, which browsers and other tools read. A header is introductory content inside the body that visitors can see, such as a site name and navigation. The title names the document in the browser tab and bookmarks and can be used in search results. The h1 is the main heading shown within the page and helps both readers and screen readers understand its subject.

Explain it 5

The events page lives at events/index.html. Explain why href="../about.html" works when you open the site from your laptop and on GitHub Pages, while href="/about.html" breaks in both places.

From events/index.html, ../about.html goes up from the events folder and then opens about.html in the site's own folder. That relationship stays the same on my laptop and when the site is published under a repository folder on GitHub Pages. A leading slash starts at the filesystem or web origin root, so /about.html skips the local project folder or GitHub Pages repository folder and looks in the wrong place.

Explain it 6

Choose one example each of <article>, <section>, <aside> and <div> from a library's website, and explain the question you asked yourself to pick each one.

I would use article for a library news post because I ask whether it would make sense on its own. I would use section for the Parking part of the Visit page because it is a themed part of a larger page with its own heading. I would use aside for related reading links because they are useful but only indirectly related to the main content. I would use div for a wrapper that centers two boxes because it is only needed for styling and has no special meaning.
